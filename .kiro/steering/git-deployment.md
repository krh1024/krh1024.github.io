# Git, 의존성 및 배포

## Git 작업 원칙

- 사용자의 **명시적 요청과 허가** 없이 다음 작업을 수행하지 않는다.
  - `git commit`, `push`, `pull`, `merge`, `rebase`
  - 브랜치 변경, 태그 생성, 원격 저장소 변경
- Git 상태나 diff 등 저장소 정보를 조회하는 명령도 실행 전에 사용자에게 허가를 받는다.

## 의존성 관리

- 새로운 npm 패키지를 추가하거나 기존 의존성 및 lock 파일(`package-lock.json`)을 변경하기 전에 이유와 영향을 사용자에게 설명하고 **별도 허가**를 받는다.
- 패키지 버전은 가능한 한 **고정(pinned) 버전**을 사용한다.
- 패키지 이름이 비정상적이거나 타이포스쿼팅 의심이 있으면 사용자에게 알린다.

## 배포 및 운영 환경

- 사용자의 명시적 요청과 허가 없이 다음 작업을 수행하지 않는다.
  - 빌드 산출물(`dist/`) 생성
  - 배포, 서버 명령 실행, 캐시 초기화
  - 운영 환경 변경

## 시크릿 관리

- `.env` 파일 및 운영 시크릿은 저장소에 추가하거나 응답에 노출하지 않는다.
- 시크릿이 포함될 가능성이 있는 파일을 커밋 대상에 포함하기 전에 반드시 사용자에게 확인한다.

## CI/CD 참고

현재 프로젝트는 GitHub Actions를 통해 GitHub Pages에 배포된다. (`/.github/workflows/deploy-pages.yml`)

- 워크플로우 파일 변경은 운영 배포에 직접 영향을 미치므로 수정 전 사용자에게 내용과 위험을 설명하고 허가를 받는다.
